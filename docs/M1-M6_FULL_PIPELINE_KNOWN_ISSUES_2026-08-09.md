# M1-M6 全链路实测问题清单（2026-08-09）

> 基于真实运行 `ui-20260809-193706-79b9eb` 整理。
>
> 输入问题：`如何训练模型使之可以从单张图片识别出物体的位置、旋转等信息？`
>
> 本轮状态：M1-M6 完整执行成功，M6 触发一次 M2 补搜并完成第二轮 M3-M6；运行层面无最终错误。以下均为**内容质量、数据契约或评测可信度问题**，不是“流程是否能跑通”的问题。

## 严重度说明

- **P0 / 严重**：会直接产生错误科学结论、虚高评分或违反用户任务边界；应优先修复。
- **P1 / 重要**：明显降低检索、图谱或实验方案质量，但不一定使流程立即失败。
- **P2 / 一般**：可维护性、展示或审计信息不完整，可在核心问题之后处理。

## M1：问题理解与任务合同

### M1-1【P0】没有识别决定方案路线的关键歧义

**现象**

原问题没有明确：

- “位置、旋转”是二维结果还是三维平移 + 三维旋转（6D 位姿）；
- 输入是纯 RGB、RGB-D，还是允许使用相机内参、物体尺寸或 CAD 模型；
- 目标是已知物体实例还是类别级未见实例。

M1 未追问或记录这些约束，M4 后续自行将任务收缩为“类别级 6D 位姿估计”。

**推荐修复**

1. 在任务合同中增加 `output_geometry`、`input_modalities`、`camera_assumptions`、`object_regime` 等字段。
2. 无法从原问题确定时生成澄清问题；比赛自动运行模式下则显式记录默认假设和不确定性。
3. M4/M5 的输出不得引入与任务合同冲突的新模态或任务范围。

### M1-2【P1】关键实体满足字面来源约束，但语义约束力不足

**现象**

“模型”“训练”等实体过于宽泛；虽然都来自原问题，但不能阻止后续从一般问题漂移到特定的类别级 NOCS 任务。

**推荐修复**

保留原文实体校验，同时把“实体合同”和“任务约束合同”分开：实体负责对象追踪，任务约束负责模态、维度、数据前提和输出形式。

## M2：文献检索与知识提取

### M2-1【P0】覆盖评估全部失败，但仍继续进入下游

**实测证据**

六个 M2 检索任务的 `search_provenance.coverage.sufficient` 全部为 `false`。最后一个评价指标补搜任务覆盖主题为 0、缺失主题为 3，仍被 M3/M6 判为缺口关闭。

**推荐修复**

1. 将 coverage 变成真正的质量门：不足时继续放宽查询、切换来源或明确输出降级状态。
2. 达到预算上限仍不足时，将未覆盖主题传递给 M3/M4/M6，禁止静默视为充分。
3. 最终报告展示每个子问题的覆盖状态，而不是只展示论文数量。

### M2-2【P0】首轮论文相关性不足

**实测证据**

空间特征子问题保留了医学图像分割、输电线分割、医学图像融合等论文；这些论文只能提供泛化的特征提取背景，不能直接支撑单目物体位姿训练方案。

**推荐修复**

1. 排序/保留裁决加入“是否直接回答原子子问题”的硬门槛。
2. 通用背景论文最多占一个 review/background 配额，不能挤占 core/method evidence。
3. 将原问题任务约束注入 QueryPlanner、Scout 和 Retention Judge，而不只传子问题文本。

### M2-3【P1】初始来源覆盖失衡

**实测证据**

初始四个子问题的 arXiv 均为 0，PubMed 均为 0；Semantic Scholar 的部分查询又通过 OpenAlex 回退，最终入选结果主要是 OpenAlex ID。第二轮放宽查询后 arXiv 才恢复结果。

**推荐修复**

1. arXiv/OpenAlex/Semantic Scholar 使用适合各自语法的查询，不直接复用包含中文实体和严格布尔表达式的查询。
2. 查询空结果时执行确定性减词/去引号/去字段限制链。
3. 区分“来源真实返回”和“跨来源回退”，避免把回退结果计作原来源覆盖。

### M2-4【P1】全文比例不足，且摘要证据与全文证据未在下游区别对待

**实测证据**

12 篇去重论文中只有 5 篇获得全文，7 篇仅有摘要；最终核心假设主要依赖一篇摘要证据。

**推荐修复**

在 M3/M4/M6 中加入证据层级权重：全文方法/结果段 > 全文其他段 > 摘要 > 元数据。仅摘要支持的具体机制和定量结论不得获得最高置信度。

### M2-5【P1】跨来源论文合并可能污染元数据

**实测证据**

`ARXIV:2406.16384`（2024 年论文）关联了标注为 2021 年的 DOI，年份明显冲突。

**推荐修复**

1. 跨来源合并优先使用一致 DOI/arXiv ID，不以模糊标题单独覆盖强标识符。
2. 合并后执行标题、年份、DOI、arXiv ID 一致性校验；冲突时保留各来源值并标记待审计。

### M2-6【P0】没有识别“候选方案已被论文完整提出”

**现象**

论文 `OA:W7128806701` 的摘要已经完整包含最终 H1 的稀疏关键点、跨模态注意力、动态邻域和多头注意力机制，但 M2 没有向 M4 输出“已有方法/不可作为新机制”的信号。

**推荐修复**

知识条目增加 `prior_method` / `novelty_blocker` 类型，或输出方法指纹；M4 生成后必须与单篇论文的方法描述做语义近重复检查。

## M3：证据图谱

### M3-1【P1】图谱结构存在，但语义关系过浅

**实测证据**

最终图谱有 135 节点、172 边，其中 134 条是通用 `involves`；真正的 `supports/extends/limits/contradicts` 数量较少。

**推荐修复**

优先构建“原子声明—原子声明”的有方向、有理由关系；来源和实体挂接边可保留，但不要让节点/边数量掩盖语义图谱覆盖不足。

### M3-2【P0】语义边缺少可审计依据

**现象**

多数语义边的 `confidence`、`rationale`、`evidence_ids` 为空，无法判断关系为何成立。

**推荐修复**

语义边必须 fail-closed：缺少证据 ID 或理由时不进入 canonical 图谱，只进入候选关系或 warning。

### M3-3【P1】冲突数据结构不一致

**实测证据**

图中存在一条 `contradicts` 边，但 `evidence_graph.conflicts` 数量为 0。

**推荐修复**

统一冲突的单一真相源；序列化前校验 `contradicts` 边与 `conflicts` 索引一致。

### M3-4【P0】证据缺口按新增数量而非相关性关闭

**实测证据**

两个 gap 因“新增 8 条/7 条知识”被关闭，但 gap 对象最终仍显示 `attempts=0`。其中“纯 RGB 是否支持双模态机制”和“具体提升幅度”并未被新证据直接证明。

**推荐修复**

1. 每个 gap 保存目标原子声明和验收条件。
2. 新证据必须与目标声明建立带 Evidence ID 的 `supports/refutes` 关系后才能关闭。
3. 记录 attempts、每轮新增证据 ID 和未关闭原因；仅新增知识数量不得作为关闭条件。

## M4：假设生成与筛选

### M4-1【P0】最终假设几乎复刻已有论文，却被判为高创新

**现象**

H1 的核心机制与 `OA:W7128806701` 摘要几乎逐项一致。M4 仍给出 novelty=0.8，独立评分又给 novelty=1.0。

**推荐修复**

1. 增加单篇论文方法近重复检测和“最接近已有工作”字段。
2. 高相似时将 novelty 封顶为低分，或将结果改写为“复现/改进假设”，必须明确新增变量。
3. Critic 必须回答“与最接近论文相比到底新增了什么”，回答不出则淘汰。

### M4-2【P0】违反单张 RGB 约束，引入未定义双模态

**现象**

机制写成“单张图片输入 → 双模态分离跨模态注意力”，而核心证据涉及 RGB/RGB-D 多模态信息。第二候选 H3 也将“单张图片”写成 RGB-D。

**推荐修复**

在生成、Critic 和契约审计三处加入输入模态硬校验；新增模态必须来自 M1 合同或被明确标成额外假设，不能静默加入。

### M4-3【P1】定量预测缺少证据或依据

**现象**

“ADD-S 提升 3 个百分点”“误差降低 10%”“关键点 50–200 个”等阈值没有相应证据或功效分析。

**推荐修复**

将预测拆成 `directional_prediction` 和 `quantitative_threshold`；后者必须绑定证据、基线统计或预实验依据，否则降级为待标定参数。

### M4-4【P1】候选假设存在内部语义矛盾

**现象**

H3 在单张图像任务中声称捕获“时间长程依赖”，且将单张图片写成 RGB-D，说明候选生成阶段仍会拼接不兼容论文机制。

**推荐修复**

Critic 增加模态、时序、任务类型和数据前提的一致性检查；矛盾候选不得进入排名。

## M5：研究计划设计

### M5-1【P0】计划验证的是已有方法，而非新假设

**现象**

实验计划结构完整，但核心模块就是已有关键点增强论文的方法，实际上更接近复现实验。

**推荐修复**

M5 接收 M4 的“novel delta”；若为空，则标题和计划必须标记为 replication/benchmark，不得包装为新研究方案。

### M5-2【P0】输入模态与模型结构不闭合

**现象**

计划一边规定单张 RGB，一边写 optional depth 和 dual-modal cross-attention，却没有定义第二模态是什么。

**推荐修复**

从 M1 任务合同生成不可变的 input specification；M5 每个数据步骤和模型分支都必须能追溯到该 specification。

### M5-3【P1】关键实验细节不足或不准确

**缺失/问题项**

- 相机内参、尺度来源、检测/分割掩码来源；
- CAD/三维模型是否已知；
- 旋转表示归一化、损失权重和对称物体处理；
- NOCS 与 YCB-Video 不同任务协议的区分；
- 多随机种子、计算资源和可复现实验配置；
- ADD 与 ADD-S 的适用对象说明疑似写反。

**推荐修复**

按计算机视觉任务类型增加领域计划模板和必填检查项；缺失时 M6 方法评审不得给高分。

### M5-4【P1】统计检验设计不足

**现象**

只写 paired t-test，没有说明独立训练次数；直接对测试图片做配对检验可能产生伪重复。

**推荐修复**

至少规定 3–5 个独立随机种子，报告均值、标准差、置信区间；明确统计单元是独立训练运行、对象实例还是图像，并根据分布选择配对检验或 bootstrap。

## M6：评审、证据裁决与评分

### M6-1【P0】事实一致性满分掩盖“复制已有论文”

**现象**

M6 自己指出 H1 与 `OA:W7128806701` 几乎完全相同，却将其视为强证据支持，给 evidence consistency 5/5，没有同步惩罚创新性。

**推荐修复**

将“是否与证据一致”和“是否只是复述证据”拆成两个硬门；前者高、后者成立时，总体评分仍必须受 novelty cap 限制。

### M6-2【P0】独立创新性把“未匹配/无路径”误当成满分创新

**实测证据**

novelty trace 中多个关系的终点没有匹配节点、`distance=null`，结果仍为 1.0。

**推荐修复**

无匹配/无路径只能返回 `unknown` 或低置信度，不得返回 1.0；同时先执行单篇方法语义相似度检查，再使用图路径评分。

### M6-3【P0】独立评分缺失值被处理成满分

**实测证据**

独立 `testability` trace 为 `null`，最终 testability 仍为 1.0；部分 atomic claim 没有 matched anchors，evidence consistency 仍为 1.0。

**推荐修复**

所有独立指标使用 fail-closed 规则：缺失、异常或无法判断时输出 `unknown` 并降低总体置信度，禁止默认满分。

### M6-4【P0】最终证据充分结论与 M2 覆盖结论冲突

**现象**

M2 六轮均判覆盖不足，M6 最终却判 `sufficient=true`、0 gap；纯 RGB 模态和具体提升幅度仍没有得到直接证明。

**推荐修复**

M6 evidence judge 必须消费 M2 coverage 和 M3 gap 验收记录；存在未解释的 `coverage.sufficient=false` 时不得输出无条件 sufficient。

### M6-5【P1】任务一致性主要依赖字面实体命中

**现象**

只要文本出现“模型、单张图片、物体、位置、旋转、训练”就得到 5/5，未识别单 RGB 与 RGB-D/双模态之间的冲突，也未惩罚任务被缩小到类别级 6D 位姿。

**推荐修复**

在实体命中之外增加结构化任务合同对比：对象、输入、输出、范围、禁止项逐字段检查；语义 LLM 只作为补充审计。

## 其他：工程、成本与协作

### O-1【P1】评分结果与流程成功状态应在 UI 中明确区分

**现象**

流程全部变绿代表模块执行完成，不代表内容已通过可信质量门。当前 4.8/5 容易让用户误以为方案已经被有效验证。

**推荐修复**

UI 分开展示：运行成功、证据覆盖、科学质量、评分置信度、已知警告。存在 P0 质量门失败时使用黄色/红色，而不是全绿。

### O-2【P1】真实运行成本较高

**实测数据**

成功续跑阶段约 708.9 秒；累计输入 96,839 tokens、输出 25,160 tokens，共约 122k tokens。历史中还曾因同步等待出现 M5/M6 停止失效，本分支已加入相应异步超时修复。

**推荐修复**

在不降低质量门的前提下缓存 M1/M2/M3、复用未变化的 M4/M5 产物，并在 UI 中展示每模块 token/耗时和超时原因。

### O-3【P2】本清单不代表自动验收通过

修复每个问题时应增加对应的回归测试或固定运行样例；删除本条目前必须附测试证据，不能只根据一次模型输出人工判断。

## 建议修复顺序

1. M4-1 + M6-1/M6-2/M6-3：阻止“复刻论文却得到满分创新”。
2. M1-1 + M4-2 + M5-2 + M6-5：冻结任务范围和输入模态。
3. M3-4 + M6-4 + M2-1：修复证据缺口和覆盖门。
4. M2-2/M2-5/M2-6：提高检索相关性、元数据与已有方法识别。
5. M3-1/M3-2/M3-3：提高图谱语义质量和可审计性。
6. M5-3/M5-4：补足实验可复现性。

## 本轮可接受的基线结论

- 可以确认：M1-M6、检查点恢复、M6→M2 补搜、第二轮 M3-M6 和 Web 观测链路已经打通。
