# M4 可取消契约审查修复设计

## 背景与根因

M4 的 `hypothesis_generator` 完成后，会同步调用任务契约语义检查。该检查把异步 Qwen 请求放进新线程，再使用没有超时的 `thread.join()` 等待。此阶段没有事件，因此网页只能看到 M4 仍在运行；Pipeline 的取消标志又只在模块开始前检查，导致用户点击“停止”后必须等待整个 M4 返回。模型请求挂起时，两条链路共同形成无限等待。

## 目标

- M4 生成器后的语义契约审查必须异步执行，并在网页事件流中可见。
- 语义审查使用一次批量 LLM 调用，避免按候选逐个串行请求。
- 语义审查有明确超时；超时后显式失败，不能静默放行。
- Pipeline 在模块运行期间轮询停止标志；收到停止请求后取消当前异步模块并保存上一模块的完整状态。
- 停止响应目标为 1 秒以内，不等待当前 M4 完整结束。

## 设计

### M4 契约审查

保留现有确定性检查，用于验证实体、需求追踪和 evidence ID。确定性检查不再调用同步语义客户端。随后新增异步批量语义审查：把所有候选假设和 M1 的 `primary_object` 实体放入一次结构化 Qwen 请求，要求为每个候选返回 `hypothesis_id`、`consistent` 和 `rationale`。

该调用通过 `_observe_tool("hypothesis_contract_auditor", ...)` 发出开始、完成和失败事件，并由 `asyncio.wait_for` 限制在 60 秒。遗漏候选、重复裁决、非布尔结论或对象不一致均作为硬门禁失败；全部候选被拒绝时沿用现有一次修复流程，修复结果也必须重新经过同一异步审查。

### 运行时取消

Pipeline 的模块包装器把模块协程创建为 `asyncio.Task`，每 0.2 秒检查一次 `threading.Event`。收到取消请求时，取消当前任务、发出 `module_cancelled` 事件并抛出 `PipelineCancelled`。Pipeline 使用进入该模块前的最后状态生成已取消结果，因此 M1-M3 已完成成果仍保留。

### 错误语义

- 用户取消：运行状态为 `cancelled`，不是 `failed`。
- M4 语义审查超时：M4 明确失败，错误信息包含超时秒数。
- 语义审查返回不完整：M4 明确失败或进入现有一次修复，不允许静默通过。

## 测试

- M4 批量审查只调用一次 LLM，并保留全部合法候选。
- M4 审查超时能在规定时间内抛出明确错误。
- Pipeline 在模块协程仍运行时收到取消标志，可取消模块并保留前序状态。
- 原有取消接口、M4、Web 和全量测试继续通过。

## 非目标

- 不重构每次运行到独立子进程。
- 不修改 M1-M3、M5-M6 的科学业务逻辑。
- 不在本次修复中调整 OpenAlex 的并行检索架构。
