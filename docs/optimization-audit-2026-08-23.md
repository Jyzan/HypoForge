## 完成情况

### 1. M2 与 M1–M6 同级

M2 的正式实现已迁移到 `hypoforge/modules/m2_literature/`。旧的
`hypoforge/literature` 只保留兼容入口，生产代码全部引用新位置；兼容测试证明
旧、新导入得到同一组类对象，避免迁移后出现双注册或类型不一致。

### 2. M4 → M2 证据缺口回访

M2 现在同时接收 M4 的 `EvidenceGapRequest` 和 M6 的 `EvidenceGap`，按问题去重，
但分别保存来源 ID。只有实际取得检索结果的缺口才会被推进状态；某个缺口失败时，
不会误把其他未检索缺口标成已处理。

离线集成测试验证的真实调度顺序为：

`M1 → M2 → M3 → M4 → M2 → M3 → M4 → M5 → M6`

### 3. 用途感知上下文管理

M4、M5、M6 不再统一读取整份图谱文本，而是根据用途构建独立上下文包：

- M4：生成、批判、排序；
- M5：按假设聚焦研究计划；
- M6：科学逻辑、方法可行性、证据充分性。

每个上下文包都包含预算、估算 token、纳入/裁剪条目 ID、裁剪原因和渲染哈希。
原始提示词不写入事件日志，但完整来源 ID 可审计。

大型图谱边界修复后，裁剪 ID 不再反向挤占 LLM 提示词预算；最终裁剪优先保留
focus 证据。基准数据：

- 旧上下文估算：60,080 token；
- 新上下文估算：28,403 token；
- 估算降幅：52.72%；
- 丢失 focus ID：0。

### 4. 网页界面

- 首页凭证默认收起，减少首屏空白；
- 新增独立视觉样式层，并通过白名单静态资源路由加载；
- 保留原有 M1–M6 详情抽屉、M3 图谱、迭代和回跳时间线；
- 新增“上下文预算”面板，实时显示上下文包、估算输入 token、纳入证据和裁剪记录；
- 420 px 窄屏无横向溢出，上下文指标自动变为两列；
- 静态资源路径遍历测试通过。

### 5. 真实运行追加修复

第一次真实快速运行发现：模型把全部实体标成 `method/outcome` 时，M1 的快速路径
没有必需 `primary_object`，最终硬校验直接终止。现已在不新增实体的前提下，从
已通过原问题来源检查的实体中提升一个主对象，并生成 `m1_contract_repaired`
审计事件。

第二个问题是快速模式把全文目标设为 0，但旧表达式使用
`configured_target or final_k`，导致 0 被错误替换为 2，继续执行预印本补搜。
现已保留显式 0，并在快速预设中关闭预印本补搜。

### 6. 真实 Token 归因与快速模式 M2 精简

供应商返回的 usage 现在由每次 Pipeline 独立的 `contextvars` 计数器记录，避免
并发网页运行互相串账。M1–M6 重复回访会累计到稳定的模块名；Pipeline 后的独立
评分单独计数，不再伪装成 M6 成本。M2 并发 Tool 另有子作用域，所以 Query
Planner、Scout 和 Paper Reader 的用量不会互相重复统计。网页新增真实 Token
分布条形图；旧历史记录没有模块明细时明确提示，而不是把各模块错误显示为 0。

同一真实问题的快速模式前后对照如下。三轮均从 M1 跑到 M6、生成假设与方案，
状态错误数均为 0；由于模型采样，子问题数和 M5 是否触发结构化重试会波动，耗时
不能只由 Token 单变量解释。

| 版本 | 子问题 | 论文 | 知识条目 | M2 调用 | M2 Token | 全链路 Token | 耗时 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| 原快速逻辑 | 3 | 5 | 11 | 26 | 59,885 | 76,083 | 92.8s |
| 精简辅助判定 | 2 | 4 | 10 | 8 | 30,306 | 43,330 | 65.6s |
| Scout 输入压缩 | 2 | 4 | 7 | 8 | 25,820 | 45,268 | 97.1s |
| M5 单次生成 | 3 | 6 | 11 | 12 | 41,114 | 56,440 | 75.5s |

“精简辅助判定”只作用于快速模式：保留语义 Scout 和 Paper Reader，把补充实体、
must/unmust 分类与分组、边界保留复审、实体同一性复审切换到代码中原有的确定性
回退。标准模式的 LLM 审核完全不变。Scout 仍审阅最多 8 篇候选，但快速模式将
每篇筛选文本从最多 6,000 字符缩至 1,800 字符；该轮 Scout Token 从 16,964
降至 13,908（约 18%）。第三轮总耗时上升是 M5 首次结构化输出未通过校验并自动
重试一次，M5 从 1 次调用变成 2 次，并非 M2 变慢。

快速模式的 M5 也不再因为词面任务锚点缺失而重新生成整套方案：第一次输出若结构
有效，只将原始研究目标确定性写回 `study_subjects`，随后重新建立 task trace；
校准仍失败才使用原有兜底方案。第四轮真实运行含 3 个子问题，M5 仅调用 1 次，
保留模型生成的 5 步研究流程并在 75.5 秒内完成。标准模式仍保留双轮生成与语义
对象审核。

## 尚存风险（不阻塞当前版本）

1. arXiv 出现过瞬时网络超时。流程能用 OpenAlex 结果继续完成，但快速模式的
   总耗时仍可能被来源级超时拉长。
2. “上下文预算”仍是本地确定性估算；新增“真实 Token 归因”来自供应商响应的
   usage。若某个兼容模型不返回 usage，该次调用只能计时、无法得到权威 Token。
3. 快速模式的实体角色提升保证流程连续，且有审计事件；它不等价于标准模式的
   独立实体复核，因此角色语义可能较粗。
4. M4 → M2 回访已通过确定性端到端调度测试；真实外网运行只有在 M4 实际提出
   证据缺口时才会自然触发，不能靠普通问题强制复现。
